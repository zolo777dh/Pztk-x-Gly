# История изменений Pztk x Glyalith

Все опубликованные изменения приложения, от первого выпуска до текущей версии. Версии расположены от новых к старым. Даты указаны для часового пояса Europe/Kiev.

## [0.1.6](https://github.com/zolo777dh/Pztk-x-Gly/releases/tag/v0.1.6) — 18.10.2026

### WCL Lab — интеграция присланного парсера

- Добавлен отдельный раздел **WCL** с вычислительным движком `bgmt x warcraftlogs lab 0.13.0`. Оригинальный Windows EXE включён в сборку, проверяется по SHA256 и запускается в фоне через его штатные команды CLI.
- Доступны выгрузка по нескольким WCL-ссылкам, повторный анализ папки или ZIP с сохранёнными raw-экспортами, поиск и анализ топ-логов, обзор специализаций, самопроверка и генерация синтетического примера.
- Добавлены ключ специализации, зоны/энкаунтеры, начальный ранг, число топ-логов и ограничение количества логов за запуск. Применяются возможности и ограничения CLI исходного движка; это не перенос всех настроек его отдельного GUI.
- Каждый запуск получает отдельную папку результатов, журнал, статус и отчёт. Обработку можно остановить; частичные результаты сохраняются и не выдаются за завершённый анализ. После закрытия приложения незавершённые запуски помечаются прерванными.
- JSON/JSONL/CSV/TXT можно просматривать внутри приложения; большие предпросмотры ограничены без сокращения файлов на диске. Доступна кнопка открытия папки результатов.
- Записанные в экспорте касты противников и выбранного игрока можно импортировать в кэш таймлайнов, затем использовать **Compare pulls & draft reminders** для сравнения и подготовки плана NSR. Повторы событий исключаются, исходные времена и участники сохраняются; синтетические примеры не считаются реальными боями.
- Сетевые команды движка требуют V2 Client ID / Client Secret. Подключение из сохранённых настроек выполняется отдельно: секрет шифруется Windows DPAPI и передаётся шифратору через stdin, без аргументов командной строки. Предыдущий независимый профиль движка восстанавливается при отключении; внешнее изменение профиля блокирует его перезапись при отключении.
- Существующие импорт V1 Client Key, импорт файлов и сравнение боёв сохранены. Наличие данных Forever и полнота профилей способностей зависят от WCL и оригинального движка; живые отчёты с пользовательскими ключами здесь не проверены.

### Выбор модели ИИ

- В Settings добавлены **Load available models** и выпадающий список для OpenAI, Claude, совместимых API и локальных серверов. Список запрашивается с ключом выбранного провайдера; для Claude поддержана пагинация.
- Ручной ввод Model ID сохранён для серверов без списка моделей. Выбор нужно подтвердить кнопкой **Save Settings**.
- В **Describe a feature** переключатель Local/Cloud переименован в **AI SOURCE**; отдельно показываются провайдер и сохранённая модель, добавлена кнопка **Choose model in Settings**. Текст запроса при переходе сохраняется.
- При пустой модели подготовка контекста сразу показывает понятное сообщение вместо ложной готовности к генерации.

### Проверки

- Добавлены проверки запуска и отмены дочернего процесса, результатов и ошибочных завершений, SHA256 движка, DPAPI-профиля, импорта кастов и списка моделей. Учтены UTF-8 BOM, вложенная метаинформация и нормализованные имена полей EXE.
- Выявлено ограничение исходного движка 0.13.0: его встроенный синтетический экспорт использует другой формат JSONL, чем ожидает повторный анализ. Такой отказ показывается как ошибка; для повторного анализа нужны сырые API-экспорты. Проверка Windows отдельно готовит синтетические данные в формате raw API.
- Интерфейс проверен на контролируемом движке: обработка → просмотр CSV → импорт кастов → сравнение боёв, остановка и отключение ключей. Проверены списки OpenAI/Claude/локального сервера и переход из запроса к выбору модели без потери текста.

## [0.1.5](https://github.com/zolo777dh/Pztk-x-Gly/releases/tag/v0.1.5) — 18.10.2026

### Экспорт и просмотр reminder packs

- Исправлен ложный отказ `Decoded pack exceeds limits` при **Export Reminder Pack** большого плана: счётчик больше не расходуется отдельно на каждый ключ и каждое значение.
- Лимиты данных согласованы с проверяемым кодом NSR: до 100 000 записей таблиц и 32 уровней вложенности на каждый профиль, с отдельными общими ограничениями инспектора.
- Учтена вложенность внешней оболочки пака и исправлено резервирование стека Lua при передаче глубоких таблиц.
- Сохранены проверки циклических ссылок, лицензирования, размера входа и распакованных данных. Добавлены явные ограничения полного JSON-представления, общего числа записей и времени обработки с отдельными сообщениями об ошибках.
- Для больших паков добавлен ограниченный предпросмотр без сокращения самого декодированного результата; **Save decoded JSON** сохраняет все поля.
- Изменение строки или ошибка декодирования сбрасывает старый предпросмотр, чтобы он не выдавался за результат нового ввода.
- Проверен экспорт плана из 4 000 напоминаний и пак с 52 000 записями. Обе строки приняты неизменённым `DecodePack` аддона NSR; полный JSON-экспорт проверен через интерфейс.

### OpenAI / ChatGPT и Claude

- Добавлен выбор **OpenAI · ChatGPT / GPT models**, **Anthropic · Claude** и другого **OpenAI-compatible API** в Settings.
- OpenAI подключается через Responses API, Claude — через Messages API с заголовками Anthropic; для локальных и совместимых серверов сохранён Chat Completions.
- Для каждого облачного провайдера сохраняются отдельные настройки модели и отдельный API-ключ в памяти сеанса. Переключение очищает поле ввода ключа и не отправляет ключ другого провайдера.
- Добавлена проверка соединения и списка моделей для выбранного провайдера. Старые настройки стороннего OpenAI-compatible сервера переносятся в соответствующий режим.
- В просмотре контекста показываются фактический провайдер и модель. Изменение провайдера, модели или endpoint после подготовки контекста требует повторного просмотра перед отправкой.
- Ответ, оборванный лимитом вывода модели, не используется как частичная замена кода.
- Обе интеграции доступны для анализа ошибок и **Describe a feature**. Для них нужны API-ключи; подписки на веб-приложения ChatGPT и Claude не заменяют доступ к API.
- Ключи ИИ по-прежнему не сохраняются между запусками; сохранение через DPAPI относится к Warcraft Logs.

### Проверки и документация

- Добавлен полный русскоязычный `CHANGELOG.md` с историей 0.1.0–0.1.5 и ссылка из README.
- Сохранено удаление раздела Try the Windows app из README, внесённое в репозитории отдельно.
- Локально пройдены 48 тестов ядра без пропусков с внешними зависимостями тестирования, основной сценарий интерфейса и отдельные проверки большого экспорта и переключения OpenAI/Claude.
- Запросы OpenAI/Claude проверены на контролируемых ответах. Живые вызовы с ключами пользователя не проверены.
- Windows-сборка опубликована; скачанный ZIP проверен по SHA256, CRC всех файлов и наличию Windows x64 EXE. Содержимое опубликованного ASAR прошло проверку запуска, IPC, локального транспорта ИИ и кодека NSR в Electron под Linux.

## [0.1.4](https://github.com/zolo777dh/Pztk-x-Gly/releases/tag/v0.1.4) — 17.10.2026

### Warcraft Logs

- Добавлен отдельный режим **V1 Client Key**: получение отчётов и событий через API V1, включая пагинацию и локальное кэширование боёв.
- Устранено смешение типов авторизации: ключ V1 больше не передаётся как Bearer-токен API V2 при выборе режима V1.
- Разделены настройки **V1 Client Key**, **V2 Access Token** и **V2 Client ID / Client Secret**.
- Для Client ID / Secret добавлены получение OAuth-токена, его повторное использование и автоматическое получение нового перед истечением срока действия.
- Добавлена настройка официального API V2 endpoint: `/api/v2/client` или `/api/v2/user`. Доступ к приватным отчётам зависит от прав токена; Client ID / Secret не заменяют вход в аккаунт пользователя.
- Добавлены **Test WCL connection** и **Check report access** для отдельной проверки API и конкретного отчёта.
- Разделены сообщения для HTTP 401, 403, 404, ограничений частоты запросов и ответа, не содержащего JSON. Ошибка API 404 больше не описывается общим советом проверить лимиты запросов.
- Для событий V1 сохраняются источник, идентификаторы и названия способностей, участники, время относительно начала боя и версия API.

### Сохранение ключей

- Добавлен **Remember Warcraft Logs key**: сохранение учётных данных между запусками через системное шифрование Electron safeStorage; в Windows используется DPAPI.
- Зашифрованные данные хранятся отдельно от `workspace.json`, экспорта и бэкапов аддонов. Сам ключ не возвращается в интерфейс при повторном открытии настроек.
- Добавлен **Forget saved key** для удаления сохранённых данных и отключения текущего доступа.
- При недоступном системном шифровании разрешено только хранение в памяти текущего сеанса. Сохранения открытым текстом нет.
- Если сохранённые данные невозможно расшифровать, приложение сообщает об этом и не заменяет их пустыми значениями без повторного ввода или явного удаления.
- Ключ облачного ИИ по-прежнему хранится только в памяти текущего сеанса.

### Проверки

- Добавлены проверки V1-запросов, раздельных режимов авторизации, пагинации событий, получения и обновления OAuth-токенов, шифрования, восстановления и удаления ключей.
- Проверен разбор ссылки на отчёт с параметрами вида `?fight=57&type=damage-done` на контролируемых ответах API.
- В Windows CI проверена цепочка: сохранение ключа через DPAPI → перезапуск приложения → восстановление доступа → удаление сохранённого ключа.
- Локально пройдены 34 теста ядра без пропусков при наличии Lua 5.1 и исходников Smart Reminders; также пройдены проверки интерфейса и упакованного приложения.
- Опубликованный ZIP скачан повторно: проверены SHA256, CRC всех файлов, Windows x64 EXE и содержимое приложения.

## [0.1.2](https://github.com/zolo777dh/Pztk-x-Gly/releases/tag/v0.1.2) — 17.10.2026

### Подключение нескольких папок

- Кнопка **+** позволяет выбрать несколько папок за одно действие через Ctrl/Shift в системном диалоге Windows.
- Можно выбрать общую директорию: приложение находит `.toc` в выбранных папках и их непосредственных подпапках и добавляет аддоны отдельными строками в список.
- NaowhForever, его модули и Naowh Smart Reminders можно подключать вместе. Состав определяется по `.toc`, без жёстко заданного списка модулей.
- Повторное подключение существующих папок не создаёт дубликаты. Список сохраняется между запусками.
- После пакетного подключения первоначально сканируется первая папка; остальные доступны для отдельного выбора и сканирования.
- **Refresh** обнаруживает новые папки аддонов в исходно выбранной директории и добавляет их в список.
- Папки, удалённые из списка вручную, не возвращаются при Refresh, пока пользователь явно не подключит их снова.
- В режиме разработки через браузер можно указать несколько путей, по одному на строку.
- На исходниках NaowhForever проверено обнаружение 14 папок, включая BiS, Combat, Discovery, DiscoveryData, DungeonJournal, JourneysData, Locales, Professions, QoL, SearchIndex, Training и Utilities.
- Добавлены проверки пакетного подключения, дубликатов, новых модулей, сохранения списка и исключения удалённых папок. Локально пройдены 28 тестов ядра без пропусков с внешними зависимостями тестирования.

## [0.1.1](https://github.com/zolo777dh/Pztk-x-Gly/releases/tag/v0.1.1) — 17.10.2026

### Предложения исправлений

- Добавлена кнопка **Suggest Fix** для проверенных локальных правил без обращения к модели.
- Первое правило разбирает ошибку ConsumableBar `attempt to call a nil value` в `CB.MacrosOn()`, связанную с отсутствующим `ns.ModuleOn`.
- Перед предложением проверяются исходный вызов и реализация настроек макросов. Если `ns.ModuleOn` существует, его вызов сохраняется; иначе предлагается обращение к настройкам загруженного модуля макросов.
- Предложение открывается как diff с проверкой Lua-синтаксиса. Исходники изменяются только после **Create Backup & Apply**.
- В объяснении отмечено, что совместимый обход не восстанавливает загрузчик основного аддона: необходимо проверить более ранние ошибки и согласованность версий файлов.

### Генерация новых функций

- Добавлен режим **Describe a feature** в Diagnostics, Patch Assistant и Project Tools.
- Можно описать нужное поведение на русском или английском и при необходимости выбрать предпочтительный существующий Lua-файл.
- Перед отправкой показывается контекст: ограниченный список файлов, загрузчик и до четырёх фрагментов исходников.
- **Generate code proposal** получает от настроенной модели код, конкретный Lua-файл и точное место вставки по уникальному фрагменту существующего кода.
- Поддерживаются вставка до или после указанного фрагмента и его замена. Итог проходит проверку Lua-синтаксиса и показывается в diff.
- Блокируются неоднозначное место вставки, неподготовленный файл, устаревшие исходники и некорректный Lua-код.
- Первая реализация ограничена одним существующим Lua-файлом за запрос. При недостаточном контексте модель должна объяснить, что требуется дополнительно.

### ИИ и сетевые ошибки

- Вместо полного большого файла подготавливается ограниченный контекст: до 24 000 символов исходного кода и сокращённые сведения об ошибке.
- Добавлены выбор **Focus line**, предварительный просмотр и отдельная отправка через **Send fragment**. По возможности выбирается целая функция вокруг нужной строки.
- Ответ с заменой фрагмента объединяется с исходным файлом. Остальные строки и окончания строк сохраняются; актуальность исходника контролируется хешем.
- Для обрезанной слишком длинной строки с генерируемыми данными разрешён только анализ, без автоматической замены.
- Устранена причина сообщения `Selected source context is too large for this request`, связанная с отправкой целого большого файла.
- Добавлены **Test local connection** и **Test cloud connection**, проверка списка моделей и объяснение, если выбранная модель не установлена.
- Нормализованы распространённые варианты API URL. Для локального `localhost` используется `127.0.0.1`.
- Неинформативное `fetch failed` заменено сообщениями о недоступном локальном сервере, тайм-ауте, DNS, TLS и настройках сети.
- Сетевые запросы настольного приложения переведены на Electron net.fetch с системными настройками сети и прокси. Проверка TLS сохранена.
- Ошибки команд передаются в интерфейс без технического префикса `Error invoking remote method 'doctor:call'`.

### Папки и интерфейс

- Добавлено меню ПКМ **Refresh / Delete folder** для подключённого аддона.
- Refresh перечитывает файлы и подпапки, выполняет повторный анализ и сбрасывает устаревшие планы исправлений. Исторические runtime-логи после обновления нужно импортировать повторно.
- Delete folder удаляет только запись из списка приложения; файлы на диске и бэкапы сохраняются.
- Убрана подпись **WoW Lua Addon Doctor** под названием **Pztk x Glyalith**.
- Проверен анализ `NaowhForever_JourneysData`: 8 Lua-файлов без найденных синтаксических ошибок; контекст большого `QuestSpots.lua` ограничен по размеру.

### ZIP и Windows-сборка

- Код приложения и зависимости упакованы в `app.asar`, вместо тысяч отдельных файлов в поставке.
- Для ZIP поставки и бэкапов используется сжатие zlib для совместимости со встроенной распаковкой Windows; переработана упаковка после сообщений `0x80004005` при извлечении JavaScript-файлов.
- Обеспечен доступ демопроекта и библиотек из ASAR. `README.md`, `VALIDATION.md` и инструкция запуска также поставляются рядом с EXE.
- Версия упаковщика и имя архива берутся из версии приложения.
- Перед публикацией Windows CI запускает упакованное приложение, проверяет IPC, локальный сетевой запрос и кодек паков, а также распаковывает ZIP средствами Windows.
- Добавлены проверки новых сценариев; локально пройдены 27 тестов ядра без пропусков с внешними зависимостями тестирования.

## [0.1.0](https://github.com/zolo777dh/Pztk-x-Gly/releases/tag/v0.1.0) — 17.10.2026

### Первое настольное приложение

- Создано отдельное приложение **Pztk x Glyalith** для Windows x64 на Electron. Для запуска готовой сборки не требуется установка Node.js, Python или Lua.
- Реализован тёмный интерфейс с синими и жёлтыми акцентами по предоставленному образцу: Diagnostics, Patch Assistant, Encounter Notes, Project Tools и Settings.
- Добавлены профили английского клиента: Retail `12.1.5.70448` и Forever `1.60.1.70425`.
- Добавлены подключение папок NaowhForever и Naowh Smart Reminders, список исходников, поиск, обнаружение TOC модулей и безопасный демопроект.

### Диагностика и работа с кодом

- Добавлен статический разбор Lua 5.1 с обработкой UTF-8, проверками загрузки файлов через TOC/XML, зависимостей, регистра путей и небольшим набором рекомендательных правил совместимости API.
- Добавлен импорт текста ошибок BugSack и данных BugGrabber из SavedVariables, сопоставление ошибок с исходниками и просмотр стека. При неоднозначном имени файла автоматическое сопоставление не выполняется.
- SavedVariables разбираются только как литеральные данные, без исполнения Lua; доступен просмотр сохранённых данных и профилей.
- Добавлены редактор полного файла, diff, проверка Lua-синтаксиса и контроль SHA256 перед записью.
- Перед применением патча создаётся ZIP-бэкап с проверкой целостности. Добавлены ручной бэкап исходников, история и восстановление с предварительным просмотром.
- Сохраняются BOM и окончания строк CRLF/LF. Изменившийся после просмотра исходник блокирует запись; ошибка бэкапа не допускает применения патча.
- Ограничена работа с путями, символическими ссылками, бинарными и неподдерживаемыми исходниками.
- Добавлен гибридный помощник: локальная или облачная OpenAI-compatible модель, настраиваемые endpoint и model ID. В первом выпуске ключи хранились только в памяти сеанса.

### Заметки и reminder packs

- Добавлены локальные планы боёв для рейдов и M+, текстовые заметки, строки назначений и напоминаний, JSON-импорт/экспорт и до 20 предыдущих редакций плана.
- Добавлены кодирование и просмотр `NSRPACK2` с LibSerialize, raw DEFLATE и совместимым алфавитом. Сгенерированный пак проверен штатным `DecodePack` аддона Smart Reminders.
- Реализован экспорт поддерживаемых текстовых напоминаний относительно начала боя, для всех игроков или отдельной роли.
- Поддерживаемые reminder-only паки можно переносить в редактор плана. Полные профили и неподдерживаемые структуры доступны для просмотра без потери полей при перезаписи.
- Лицензированные и производные паки не перепаковываются; обхода ограничений лицензирования нет.

- Различаются наблюдаемые нажатия и рекомендуемые действия. Смешение разных энкаунтеров, сложностей, известных несовместимых сборок и дублирование попыток ограничены проверками.

## Текущие ограничения

- Работоспособность изменённого аддона внутри игры проверяет пользователь. Статический анализ не заменяет игровой клиент, полный каталог WoW API, проверку taint или combat lockdown.
- Приложение читает исходники, импортированные ошибки и сохранённые файлы; прямого чтения памяти игры и непрерывного доступа к виджетам во время игры нет. SavedVariables отражают последнее сохранение клиента.
- Предложения кода применяются после просмотра diff и команды пользователя с бэкапом. Генерация новых функций пока ограничена одним существующим Lua-файлом за запрос; локальная модель в поставку не включена.
- Живая загрузка конкретного отчёта WCL с ключом пользователя в облачной среде не проверена. Доступность API V1, права на отчёт, срок действия токена и покрытие Forever зависят от сервиса и учётных данных.
- Автоматическая сегментация целого M+ забега на боссов, выравнивание фаз, генерация заметок моделью и полноценное исправление нескольких файлов одной операцией пока не реализованы. Среднее по логам не доказывает оптимальность выбранного защитного заклинания.
- Экспорт reminder packs ограничен проверенным форматом и подмножеством напоминаний; тайминги и энкаунтер нужно проверить в игре.
- Бэкапы содержат исходники, а не полную копию игры, медиаресурсов или папки WTF. Сборки приложения пока без цифровой подписи.
- Приложение не создаёт коммиты и не выполняет push в репозитории NaowhForever и NaowhSmartReminders. Публикация через GitHub Actions относится к репозиторию самого приложения.
