Pztk x Glyalith 0.1.11 — быстрый старт

Defensive planner:
1. WCL → Defensive profile planner.
2. Выберите специализацию и подземелье.
3. Import profile / HTML → выберите исходный NSR-профиль или таблицу защит для этого спека.
4. В списке слева выберите НИП/босса, в среднем — его способность.
5. Справа выберите доступный набор защит. Назначение сохранится автоматически.
6. Export NSR → Copy NSR string → вставьте строку в NSR внутри игры.
Тайминг доступен в Timing and IDs; полный редактор и анализ логов — в Advanced tools.

Способности ограничены выбранным НИП и подземельем. Для треша нужен ExBoss;
NSR использует mapID + spellID, без отдельного NPC-фильтра во время срабатывания.
Таблица без spell ID защит не может сама создать корректный набор: добавьте эти ID
через редактор или импортируйте исходный NSR-профиль. Рекомендации не считаются логом нажатий.

Diagnostics: выделите папки через Ctrl/Shift, выберите версию игры и Scan selected (N).
Проверятся только выделенные аддоны под одной выбранной версией.
WCL runs & results после запуска пуст; сохранённые файлы и ключи не удаляются.

Предыдущие возможности и подробности:

Pztk x Glyalith 0.1.10 — Windows x64

1. Распакуйте ВЕСЬ архив в отдельную папку.
2. Запустите «Pztk x Glyalith.exe». Не переносите EXE отдельно от ресурсов и DLL.
3. Нажмите «Open disposable demo», чтобы проверить интерфейс на безопасном примере.
4. Кнопка + возле Addons позволяет выбрать сразу несколько папок через Ctrl/Shift.
   Либо выберите общую папку: аддоны с .toc в ней и её подпапках появятся в списке.
5. Выберите Retail или Forever, нажмите Scan Project.

Патчи: Patch Assistant → Validate & preview → Create Backup & Apply.
Перед записью создаётся и проверяется ZIP. Откат: Project Tools → Restore.
Бэкап содержит исходники; это не копия всей игры или папки WTF.

Заметки: Encounter Notes. Сравнение логов и импорт файлов: Encounter Lab.
Поддерживаются структурированный HTML/JSON и таблицы HTML/CSV с сопоставлением столбцов.
Среднее считается по выбранным наблюдениям; рекомендации и реальные нажатия различаются.

ИИ: задайте локальную OpenAI-compatible модель (например, Ollama) или облачный API в Settings.
Модель не включена в архив. Ключ облачного ИИ действует только до закрытия приложения.
Warcraft Logs: в Settings выберите V1 Client Key, если у вас ключ V1.
Для V2 отдельно доступны Access Token или Client ID / Client Secret.
Remember Warcraft Logs key + Save Settings сохраняет ключ через Windows DPAPI.
Test WCL connection проверяет API; Check report access — вашу ссылку на отчёт.
Forget saved key удаляет сохранённые данные. Без ключа работают импорт файлов и кэш.

Это тестовая версия, без цифровой подписи. Работу EXE на Windows и аддонов внутри игры
нужно проверить на вашей машине. Полного каталога WoW API и автоматической проверки поведения
в игре пока нет. Подробности — README.md и VALIDATION.md рядом с EXE.

ПКМ по аддону: Refresh перечитывает файлы и подпапки; Delete folder удаляет только из списка.
Suggest Fix предлагает проверенные локальные исправления. AI-анализ сначала показывает контекст.
Describe a feature: опишите функцию → Prepare feature context → Generate code proposal.
Приложение укажет Lua-файл и место вставки, проверит синтаксис и покажет diff перед применением.
Генерация требует настроенной модели. В этой версии — один существующий Lua-файл за запрос.
В GitHub-репозитории аддонов приложение ничего не публикует.

ИИ: Settings → ChatGPT / Claude → выберите провайдера, модель и его API-ключ.
Подписка на ChatGPT/Claude не заменяет API-доступ. Ключи разных ИИ разделены и действуют до закрытия.
Большие паки: предпросмотр сокращается; Save decoded JSON сохраняет полный результат.
Исправлен ложный лимит Export Reminder Pack; проверен план из 4 000 напоминаний.

Выбор ИИ: Settings → Load available models → выберите модель из Available models → Save Settings.
Model ID также можно ввести вручную. В Describe a feature кнопка Choose model in Settings
открывает настройки, сохраняя текст запроса; Local/Cloud теперь называется AI SOURCE.

WCL: вкладка WCL содержит присланный движок bgmt x warcraftlogs lab 0.13.0.
Начните с Check engine installation. Analyze saved export повторно анализирует его raw-папку
или ZIP локально. Export WCL links принимает несколько ссылок с fight/source.
Также доступны топ-логи, обзор специализаций, самопроверка и синтетический пример.
Для сетевых команд сохраните V2 Client ID / Client Secret в Settings и нажмите
Connect saved V2 client to Lab. Это отдельно сохраняет ключ движка через Windows DPAPI,
даже если Remember key в Settings выключен. Disconnect Lab client убирает эту связь
и восстанавливает предыдущий независимый профиль, если он был. V1-импорт остаётся
в Encounter Notes; ключ V1 не заменяет OAuth-клиент для встроенного движка.

Результаты: выберите запуск, просмотрите JSON/CSV или Open result folder.
Import casts возле fight.json добавляет реальные касты в кэш таймлайнов.
Compare pulls & draft reminders открывает сравнение боёв и подготовку плана NSR.
Синтетические, прерванные и неуспешные результаты не считаются реальными завершёнными боями.

Поиск: Ctrl+F — текущий редактор (включая черновик); Ctrl+Shift+F — все папки Addons.
Enter/F3 и Shift+Enter/Shift+F3 переключают совпадения, Escape закрывает поиск.
Глобальный поиск читает файлы на диске; черновики сохраняются в памяти при переходах.

WCL → Defensive profile planner:
1. Импортируйте исходную строку профиля NSRPACK2 и выберите нужный профиль.
2. Прикрепите HTML/CSV/JSON; сопоставьте столбцы и подтвердите реальные нажатия.
   Нужны dungeon, encounter, bossSpellId, specId, defensiveSpellId, bossTime,
   defensiveTime и sample; добавляйте player, occurrence, difficulty и build.
   Шаблон CSV доступен в окне. Времена — секунды или m:ss относительно начала боя.
3. Выберите spell ID механик; задайте dungeonEncounterID / instance mapID
   и проверьте ключ способности у таймер-провайдера. Можно назначить кэшированные
   логи конкретным игрокам и специализациям. Полный M+ забег сначала разделите на бои.
4. Analyze defensive presets → проверьте средние → подтвердите ID → Preview.
5. После просмотра скопируйте новую строку и импортируйте в NSR. Оригинал сохранён.
HTML-пример Holy Paladin содержит приоритеты и времена механик, а не защитных нажатий.
Без реальных нажатий среднее и временная привязка не генерируются.
NSR хранит одно время на способность/набор; треш требует ExBoss. Это приоритеты
наблюдаемого использования, не доказанная оптимальная ротация и не автонажатия.
Совместимость экспорта проверена на предоставленном Retail NSR; игровые срабатывания
в Retail/Forever необходимо проверить самостоятельно. Файлы аддона не изменяются.

Исправление 0.1.8: derivedFrom — отметка происхождения, а не лицензия аккаунта.
Такие строки можно импортировать и дорабатывать; исходные автор и название
сохраняются при экспорте профиля и напоминаний. Паки с :LIC1: проверяются в NSR.

Исправление 0.1.9: верхняя строка показывает версию запущенной сборки.
В 0.1.7 и 0.1.8 надпись ошибочно оставалась 0.1.6, хотя код был обновлён.

Визуальный редактор NSR (0.1.10):
WCL → Defensive profile planner → Import NSR profile автоматически открывает окно.
Также: Project Tools → Inspect reminder pack → Decode → Open visual profile editor.
Defensive sets: выберите специализацию/набор, измените имена, spell ID, порядок,
Together; Save profile edits сохраняет рабочую копию отдельно от оригинала.
Encounters & spells: редактируйте настроенные в профиле encounter ID, spell ID,
набор и время предупреждения. Названия берутся из доступных справочников/таблиц/логов;
если имени нет, показан ID, его можно подписать. Полного живого журнала вне игры нет.
Trash rules: правила ExBoss, instance mapID, способность, набор и тайминг.
Import defense tables: HTML/JSON как пример Holy Paladin → Preview → Apply.
Можно импортировать только наборы либо выбрать босса и подтвердить его ID/ключ таймера.
Таблицы реальных нажатий открывают анализатор, сохраняя рабочий профиль.
/Export profile → Copy / Save NSR string → импортируйте в NSR и проверьте в игре.
После расчёта средних кнопка Edit generated defensive profile открывает редактор снова.
Другие профили, настройки и напоминания сохраняются. Рабочая копия возобновляется;
закрытие окна сохраняет допустимые изменения формы и передаёт их планировщику.

Настройка без логов (0.1.10):
WCL → Defensive profile planner → Create empty NSR profile (или Import NSR profile).
Defensive sets → выберите специализацию по названию → создайте набор способностей.
NPC & ability database → подземелье → НИП → способность → Configure selected ability.
В открытой форме назначьте набор, время предупреждения, Enabled → Save profile edits.
/Export profile → Copy edited NSR string → импортируйте в аддон NSR.
База охватывает восемь указанных подземелий, 248 записей НИП / 1029 связей со способностями.
Данные MDT/LittleWigs — снимок 18.10.2026, источники указаны в окне базы.
Неподтверждённый encounter/timer ID можно проверить и исправить вручную.
Для треша NSR использует instance mapID + spellID и ExBoss, без фильтра по NPC ID.
Сам выбор НИП помогает найти способность; это не добавляет отсутствующий таймер в NSR.

Addons: Ctrl+A, Ctrl+click, Shift+click и Shift+перетаскивание выделяют папки.
ПКМ → Refresh / Delete работают с выделением; Delete убирает папки только из списка.
После запуска Addons и список активных логов пусты. Профили, бэкапы, заметки,
таблицы и сохранённые ключи WCL остаются на месте; нужные папки/бои подключите снова.
Encounter Lab / Planner: выбор подземелий по названиям, instance mapID и Challenge Mode ID
хранятся отдельно. Специализации выбираются по названиям (102 Balance, 104 Guardian Druid).
Cloud AI: список запрашивается у выбранного провайдера с вашим ключом и обновляется
при смене ключа/провайдера. Возвращённый список не подтверждает остаток квоты.
Названия неизвестных способностей уточняются через публичный English tooltip и кэш;
при недоступном источнике ID остаётся видимым, имя можно задать вручную.
Important abilities: загрузка Method / сохранённый HTML / ручная отметка способности.
Семь названий Altar of Fangs внесены по скриншоту без выдуманных ID. Остальные списки
Method не подтверждены: облачный сетевой шлюз возвращал HTTP 403.
